# Package SpringBrand as explicit native Host Adapters

SpringBrand will keep one Canonical Skill and one production MCP endpoint, then add explicit native Host Adapters for Claude Code, Cursor, and Tencent WorkBuddy. A separately named `springbrand-dev` distribution may reuse those Adapter assets for internal testing against the fixed development endpoint. Each Adapter owns only the manifest, Marketplace metadata, MCP representation, routing mechanism, and lifecycle details that its host actually requires. We will not add a generic runtime abstraction or custom multi-host installer; explicit manifests plus invariant validation are smaller and preserve each host's native lifecycle.

## Decisions

- **Shared source of truth:** `skills/springbrand/SKILL.md`, `VERSION`, and `https://connector.springbrand.ai/mcp` remain canonical. CI must verify every manifest version, endpoint, and Distribution Mirror against them.
- **Claude:** one `claude-code` Host Adapter covers the Claude Code CLI and the Claude Desktop Code tab because they share the Claude Code plugin engine and core configuration. They remain separate Surfaces with separate Native Evidence. The package uses `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, root `.mcp.json`, and Claude-native `UserPromptSubmit` routing. Claude Desktop does not require a GUI-only installation path: using the native `claude plugin marketplace add/install` CLI is accepted, provided Desktop itself proves Plugin loading, OAuth, routing, update, and removal. Direct configuration edits and custom installers remain forbidden.
- **Cursor:** target the desktop app, not Cursor CLI, in this delivery. Use Cursor's native **Customize → Browse Marketplace → Add Marketplace → Import from GitHub** flow with this repository as the primary distribution path; a public Cursor directory listing is optional, not a `1.2.0` release gate. Package a self-contained Marketplace plugin under `plugins/springbrand/`, registered by `.cursor-plugin/marketplace.json`. Because the canonical Skill stays at the repository root, the nested Cursor package is a generated Distribution Mirror with a drift check. Use an `alwaysApply: true` Rule for preflight routing; Cursor's `beforeSubmitPrompt` Hook can allow or block but cannot inject routing instructions, so an executable routing Hook would not meet the requirement. The GitHub import flow and update/removal behavior must pass Native Evidence before release.
- **WorkBuddy:** self-distribute through a third-party GitHub Plugin Marketplace using `.codebuddy-plugin/marketplace.json` and a self-contained `.workbuddy-plugin/plugin.json` package. Its nested Skill and Hook assets are generated Distribution Mirrors of canonical root assets, with drift checks. The built-in WorkBuddy Connectors catalog and a Tencent partner listing are outside `1.2.0`. Try the shared-engine `UserPromptSubmit` Hook only through a native WorkBuddy validation; do not claim support from schema inspection alone.
- **Hook trust:** accept each host's native trust boundary and do not simulate a stricter one. For WorkBuddy, installing and enabling the Plugin is the accepted trust decision for its Plugin-level Hook. The Hook must be static, local, network-free, must not persist prompts, and must be disclosed in the installation guide.
- **Routing precision:** Hook and Rule layers only remind the Agent to apply the Canonical Skill's capability-gap gate. Transformations of supplied material, routine local work, planning without execution, and SpringBrand/MCP diagnosis continue directly. Complete-catalog fallback is conditional and never follows a transport or provider error.
- **OAuth:** every Adapter declares only the native remote HTTP endpoint. Do not ship static tokens, `Authorization` headers, client secrets, API-key prompts, or extra OAuth resource parameters. Authentication belongs to each host's native MCP OAuth flow.
- **Lifecycle:** installation, enablement, authentication, trust, update, disablement, and removal use the host's native Plugin/Marketplace mechanisms. No configuration writer or AgentKey-style all-agent installer is part of this delivery.
- **Release boundary:** complete and validate the Claude, Cursor, and WorkBuddy production Adapters before cutting one combined **`1.2.0` stable** release. Do not publish per-host production releases. The approved `springbrand-dev` internal-testing prerelease is a separate Plugin and MCP identity, does not move `stable`, and does not satisfy production Native Evidence. Keep `stable` on `1.1.1` until every required production Surface passes Native Evidence.
- **Platform scope:** `1.2.0` requires Native Evidence on macOS only: Claude Code CLI, Claude Desktop Code tab, Cursor desktop, and WorkBuddy desktop. Windows is explicitly unverified and must not be advertised as supported until separate Native Evidence exists.
- **No duplicate MCP registration:** once a Plugin bundles `springbrand` or `springbrand-dev`, guidance must authenticate that entry rather than creating a second global server. Do not enable the two complete Plugins together; the manual shared-Skill fallback may coexist because its MCP entries have distinct names.
- **Legacy migration:** native Plugin installation must not automatically delete a pre-existing global SpringBrand Skill, MCP entry, OAuth state, or unrelated configuration. Detect and report duplicate SpringBrand entries; remove or replace only the named legacy SpringBrand entry with explicit user approval.
- **Evidence gate:** schema validation is necessary but not acceptance. Every supported Surface must independently prove Skill visibility, SpringBrand OAuth, routing-before-work behavior, update/removal cleanup, and preservation of unrelated configuration. Routing-before-work is mandatory: if WorkBuddy `UserPromptSubmit`, Claude routing, or the Cursor always-on Rule cannot enforce discovery before planning or production, the entire `1.2.0` release is blocked; no Surface may silently degrade to Skill + MCP only.

## Reference

AgentKey at commit [`efc28096918b8565d495cacb6864b17f59cc7214`](https://github.com/chainbase-labs/AgentKey/commit/efc28096918b8565d495cacb6864b17f59cc7214) demonstrates the useful baseline: one shared Skill, explicit Claude/Codex/Cursor manifests, host-specific MCP shapes, synchronized versions/endpoints, and header-free native OAuth. Its latest Claude fix also demonstrates why an explicit `Authorization` header prevents OAuth fallback. AgentKey does not package Hooks, and its closed Cursor indexing fix reports that a root `source: "./"` package indexed zero plugins; those gaps are not treated as proven SpringBrand behavior.
